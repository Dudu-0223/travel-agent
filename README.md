# travel-agent

DeepSeek Harness 插件：旅行助手。`~/travel` 工作区里的每个会话就是一个行程文件夹。

- **主页**（左侧栏「旅行助手」）：列出 `~/travel` 里的会话，每个一张文件夹卡片，显示行程标题、路线、方案数、最低价、最少请假天数和是否正在查询。点卡片进入这个会话。底部输入框发一条消息就新建一个会话（新文件夹）并进入。卡片上的「归档」用 DSH 的会话归档，主页底部「已归档」可以恢复。
- **会话里的「机票方案」视图**：这个会话的文件夹、推荐方案、方案详情。推荐方案按价格、请假天数、转机次数逐层取不被支配的方案（`model.js` 的 `rankOptions`），整层加入，直到至少 5 个；第 1 层带最便宜 / 最省假 / 最好飞标签，之后的标「备选」。回程的到家日期和时间用绿色「到家」标出；「‹ 全部行程」回主页；「在侧边栏看运行过程」用 DSH 右侧栏打开这个会话的聊天过程。方案详情里的「归档」只在这台电脑的浏览器里隐藏单个方案（localStorage `dsh-travel-agent.archived`），最优方案按没归档的重算。
- 输入框、ask_user_question 提问卡片、对话 / 轨迹视图、右侧栏都是 DSH 自带的。其他会话的标题栏也会出现「机票方案」，没有行程数据时只有一个回旅行助手的按钮。

`~/travel` 里放着助手的说明 `AGENTS.md` 和查票 skill `.agents/skills/find-flights/SKILL.md`，改这两个文件就能调整助手的行为。仓库的 `workspace/` 是它们的副本：在新机器上执行 `mkdir -p ~/travel && cp -R workspace/. ~/travel/ && git -C ~/travel init`（`.git` 让 DSH 把 `~/travel` 当作项目根，才会加载这两个文件）。改了 `~/travel` 里的文件后记得同步回 `workspace/`。

- `model.js`：纯逻辑。参数校验、机场时区、飞行与转机时长、请假天数、帕累托最优。
- `index.js`：Host 端。注册 `flight_*` 工具（只对工作目录是 `~/travel` 的会话开放）；投影 `flightBoard`（完整方案，打开会话时用）和 `flightTrip`（文件夹卡片摘要，随会话列表下发）。
- `client.js`：主页、机票方案视图、左侧栏入口。

安装：插件管理 → 添加插件 → 选择本目录。修改后在插件管理里重新启用 `travel-agent` 即可重新加载。
